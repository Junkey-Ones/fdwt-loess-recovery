# 脚本书写规范

> 本规范是 [[项目系统架构]] 的强制执行细则。本项目**所有脚本（src/M0–M10、workflow、tests）必须严格按照此规范书写**；任何脚本在进入流水线前按文末检查清单逐条核对，一条不满足即不得合入。
> 用语约定：**必须**＝硬性要求，违反即为不合规；**应**＝默认做法，偏离须在 scr_XX.md 中说明理由；**可**＝可选。

## 1. 适用范围与总则

1.1 本规范适用于仓库内全部代码：`src/M0`–`src/M10` 科学脚本、`workflow/` 编排脚本、`tests/` 测试脚本。
1.2 **科学逻辑与调度逻辑必须分离**：科学代码只出现在 `src/`，编排代码只出现在 `workflow/`。workflow 中不得出现任何科学参数或数据处理逻辑。
1.3 **一个脚本只做一件事**，且其功能必须与所属模块（M0–M10）的职责一致；不得把多个模块的逻辑塞进一个脚本。

## 2. 文件与命名

2.1 脚本文件名**必须**为小写 snake_case，格式 `scr_{动词或对象}_{简短描述}.py`，如 `scr_detect_flash_drought.py`；**不得**使用中文、空格、大写字母。
2.2 每个脚本**必须**配同名 `scr_XX.md`，至少包含：功能一句话、输入（数据名+来源）、输出（数据名+去向）、运行方式、已知限制。文档与代码不同步视为不合规。
2.3 所有新字段名、输出表列名、文件名**必须**小写 snake_case；禁止缩写自造词（沿用协议命名的除外，如 `episode_id`、`t_min`）。
2.4 时间戳**必须**用 ISO 8601（`YYYY-MM-DDThh-mm-ss`），仅允许出现在日志文件名、`run_alias` 前缀与登记字段；**不得**出现在任何参与科学结果哈希的路径或内容中。

## 3. 参数（最核心条款）

3.1 **科学参数只允许从 `config/params.yaml` 读取**——阈值、时期、窗口、种子、产品选择等一律如此。
3.2 脚本代码中**禁止出现科学参数的魔法数字**。判断示例：`if smp < 0.40` 不合规；`if smp < params["smp_termination_threshold"]` 合规。（纯技术常量如数组大小、重试次数可局部定义，但须加注释 `# technical constant`。）
3.3 随机过程**必须**使用 `params.yaml` 中登记的种子，**不得**自行生成随机种子。
3.4 脚本**不得**拥有自己的参数文件；**不得**在命令行接受科学参数（技术开关如 `--resume` 除外）。
3.5 读取配置**必须**通过统一入口（workflow 层提供的 config loader），**不得**各脚本自行拼路径解析 YAML。

## 4. 输入输出

4.1 **路径全部来自配置与运行上下文**，脚本中禁止硬编码绝对路径或 `../` 相对穿越。
4.2 **上游只读**：只能读取本模块在依赖图中声明的上游产物与 `data/raw`；**严禁**写入 `data/raw`，严禁修改上游模块的任何输出。
4.3 **下游只写自己的位置**：输出**必须**写入 `data/{interim|frozen}/{数据名}/{run_alias}/` 或 `outputs/{run_alias}/` 下本模块的既有文件名（按 `schema_registry.yaml` 登记），**不得**自创目录层级。
4.4 **原子写出**：先写临时文件再原子改名（如 `*.tmp` → rename），**不得**留下半截文件供下游读取。
4.5 每次运行**必须**在各输出目录写入/更新 `run.json`（run_id、参数哈希、代码哈希、种子、git commit、模块），并登记 `metadata/run_index.csv`。
4.6 输出表**必须**符合 `schema_registry.yaml`；未发生的表**必须**保留空表和表头，**不得**因"无数据"而省略文件。
4.7 写入 `data/frozen` 时**必须**先检查目标已存在则报错退出（`overwrite_frozen=false` 语义），**不得**覆盖。

## 5. 运行契约

5.1 所有模块**必须**通过统一入口 `run_module(module_id, config_path, run_id, run_alias, resume, overwrite_frozen)` 被调用；**不得**绕过入口直接以 `python scr_XX.py` 投入生产运行（调试除外，调试产物**必须**写入临时 run_alias，**不得**混入正式版本）。
5.2 脚本**必须**幂等：相同 (params_hash, code_hash, seed, 上游输入) 重复运行产出完全一致的结果。
5.3 模块**必须**在开始时校验上游产物存在且 `run.json` 哈希与期望一致，不一致即报错终止，**不得**"猜测着继续跑"。
5.4 **默认入口为交互式向导**：在终端直接运行入口（`python -m workflow.run_module`）后，**必须**依次以中文问答收集运行信息，用户通过选择/输入控制运行，**不得**要求用户背诵命令行技术开关。向导**必须**依次询问并校验：
	1. **运行范围**：整体运行（M0→M10）还是指定模块（单选/多选，列出各模块中文名）；
	2. **run_alias**：**必填，不传不允许启动**（规则 A）；按 `YYYY-MM-DD_短描述` 校验，并在末尾确认页回显输出路径；
	3. **运行模式**：全新运行 / `resume` 断点续跑（有未完成运行时才出现此问）；
	4. **产品组合/规范变体**：仅当存在多个已登记选项时询问，选项**必须**从 `specification_matrix.yaml` 与 `product_combo` 预登记条目中列出供选择，**不得**让用户自由输入；
	5. **进度显示**：自动、彩色实时面板、逐行文本，默认自动；
	6. **确认计划**：展示纳入上游依赖后的模块顺序、运行别名、数据组合、规范变体及中间数据、冻结交接、结果输出、运行日志四类路径。用户明确选择继续后方可提交。
5.5 **向导红线**：只收集运行控制信息，**严禁**在向导中询问任何科学参数（阈值、时期、窗口、种子等）；一切科学口径只能来自 `config/params.yaml`。违反即为不合规。
5.6 向导**必须**全中文、一次一问、显示默认值；输入不合法时**必须**用中文说明原因并重新提问，**不得**崩溃或静默取默认。
5.7 为 CI 与批量调度保留非交互命令行参数作为高级入口，**必须**与向导复用同一套校验函数（单一实现，不得两套逻辑）；交互向导是文档与示例中的**唯一推荐用法**。

## 6. 留痕与日志

6.1 **禁止**用 `print` 作为唯一日志手段；**必须**使用统一 logger 输出结构化 JSONL 至 `logs/{run_alias}/{M模块}/{M模块}_{脚本名}_{ISO8601}.jsonl`，含 `level`、`time`、消息与 stdout/stderr。
6.2 一个日志文件写完即封存；续跑**必须**生成新时间戳文件，**不得**修改已封存文件。
6.3 样本流留痕：任何涉及样本筛选的模块**必须**向 `sample_flow.csv` 逐层写入 `n_before`、`n_after`、排除原因；**不得**只记最终数量。
6.4 模块结束时**必须**更新 `module_status.csv` 为协议枚举值之一（`not_run/passed/descriptive_only/conditional_skipped/exited/failed`），**不得**自造状态值；条件性退出**必须**同时产出约定的 gate/exit 报告文件。
6.5 发生预注册偏离**必须**写 `config/deviation_log.csv`（含"是否见过结局"字段）；未发生也**必须**保留空表。

## 7. 敏感性与变体

7.1 一切敏感性分析（规范曲线、产品组合、暴露版本、物候模式）**必须**由 `config/specification_matrix.yaml` 与 `product_combo` 配置驱动。
7.2 **严禁**"复制一套脚本改几个数字"来做敏感性；同一流水线跑 N 遍是唯一合法方式。
7.3 分支/条件逻辑**必须**显式来自配置枚举，**不得**靠注释掉代码行切换分析口径。

## 8. 测试

8.1 关键函数（事件识别、结局派生、阈值判定）**必须**有 `tests/` 单元测试，对应《SOP 附录》§15.1 测试矩阵（U/E/G/C/L/N/P/T/S/D/R/V）。
8.2 **不得**用 skip 冒充 pass**：测试不适用须写明原因；测试结果**必须**落盘为 `outputs/{run_alias}/reports/sop_unit_test_result.csv`。
8.3 合成序列测试**必须**覆盖：闰年、累计边界、阈值临界、缺测、删失、湿窗口。

## 9. 注释与文件头（必须中文）

9.1 脚本内**所有**注释、docstring、函数说明**必须使用中文**；协议专有名词（`episode_id`、`P95`、`cloglog` 等）保留英文原名，其余解释性文字一律中文。
9.2 每个脚本开头**必须**有规范的文件头 docstring，**必须**依次写清：脚本名、所属模块与一句话功能、作者、版本号、读什么数据（从哪读）、生成什么数据（存放在哪）、日志等其他文件存放在哪；另附运行示例与退出码。模板如下（字段不得缺项，没有的写"无"）：

```python
r"""脚本名：scr_detect_flash_drought.py（M4 · 全量骤旱事件识别）

功能简介：按 SMP 阈值与下降速率逐格点扫描候序列，
  产出全量事件库 event_master_base 与候选审计表，主键 episode_id。

作者：Junkey
版本：v1.0.0（更新日期：2026-11-10）

读取数据：
  - grid_pentad（M3 交接，SMP 连续序列）← data/frozen/{run_alias}/grid_pentad/
  - 阈值与时期参数 ← config/params.yaml（无本地参数文件）
生成数据：
  - event_master_base.parquet → data/interim/event_master_base/{run_alias}/
  - event_candidate_audit.parquet → data/interim/event_candidate_audit/{run_alias}/
其他文件：
  - 运行日志 → logs/{run_alias}/M4/（JSONL，统一 logger 写入，文件名含运行时刻）
  - 样本流 → 追加 sample_flow.csv；模块状态 → 更新 module_status.csv

运行示例（从项目根目录）：
  python -m workflow.run_module M4 --run-alias 2026-11-10_主分析
退出码：0 成功，1 执行失败，2 预检失败，130 中断。
"""
```

9.3 文件头中的路径**必须**与实际配置一致；改动输出去向时**必须**同步更新文件头与 `scr_XX.md`，二者与代码不一致视为不合规。
9.4 变量与函数名 snake_case；类名 PascalCase；公开函数**必须**有中文 docstring（输入、输出、单位、坐标/时间约定）。
9.5 依赖**必须**写入 `environment.yml` 并锁定版本；**不得**使用未登记的第三方库。
9.6 研究区、时期、单位换算等项目级常量**必须**来自 `params.yaml` 或 `metadata/`，**不得**散落各脚本。
9.7 交互式探索（EDA、临时作图）**必须**放在 `notebooks/` 或一次性脚本目录并标明"非生产代码"，**不得**与 `src/M*` 生产脚本混放，其产物**不得**进入 `frozen/` 与论文图表。

## 10. 终端交互：动态面板与中文输出

10.1 终端交互和运行进度**必须**复用本仓库 `workflow/terminal_panel.py`。从仓库根目录以包路径 `workflow.terminal_panel` 导入 `WizardPanel`、`LiveStatus`、`ChineseHelp`、`ChineseParser`、`check_progress` 或 `validate_progress`。统一编排入口管理面板生命周期。科学脚本通过运行上下文上报进度，由入口集中渲染。
10.2 `rich` **必须**登记进 `environment.yml` 并锁定版本；面板组件**不得**读取数据文件、**不得**含科学逻辑。
10.3 **必须**提供 `--progress {auto,panel,plain}` 参数，默认 `auto`：交互终端启用面板，非交互环境（重定向、CI、管道）自动降级为逐行输出；**不得**因无 TTY 而崩溃或输出乱码。
10.4 面板内容**必须**为中文。运行阶段使用 `LiveStatus(mode, render)`，在任务开始前调用 `start()`，在 `finally` 中调用 `close()`。渲染回调只读取当前状态，通过 `status.panel.draw(title, context, step, detail, statistics, elapsed, fraction)` 显示运行标题、上下文、步骤、明细、统计量、耗时和进度。 `fraction` 为 0–1 的比例。
10.5 **运行状态、命令行帮助（`-h`）、警告、错误提示、退出说明一律使用中文**：argparse 的 description/help **必须**通过 `ChineseParser`/`ChineseHelp` 输出中文；异常**必须**在顶层捕获并给出中文提示后再按退出码退出（0/1/2/130，语义见文件头）。
10.6 JSONL 日志**字段名保持英文** snake_case（机器解析用），但 `message` 等可读内容**必须**用中文。
10.7 面板、交互提示和逐行反馈使用标准错误（stderr），结构化结果使用标准输出（stdout）。

10.8 启动选项**必须**由编排入口在 `with WizardPanel(title) as panel:` 中统一收集。单选题调用 `panel.menu(prompt, options, default, section=..., details=..., check=...)`，`options` 每项为 `(内部值, 中文标签, 用途说明)`。组件负责编号、标记默认值和重试。自由输入和模块多选调用 `panel.ask(prompt, check, default, section=..., details=..., hint=...)`。校验函数返回有效值，输入无效时抛出带中文说明的 `ValueError`。

10.9 向导**必须**沿用统一样式。紫色标识阶段，青色标识选项编号，绿色标识默认值，黄色标识操作提示，红色标识校验错误。逐行模式也须显示编号、默认值和校验反馈。交互终端保留原生输入与中文输入法，离开向导或中断时恢复终端画面。

## 11. 合入前检查清单（逐条打勾，一条不满足即不得进入流水线）

- [ ] 文件命名 snake_case，位于正确模块目录，配 `scr_XX.md`
- [ ] 文件头 docstring 七项齐全（脚本名/功能/作者/版本/读什么从哪读/生成什么存哪/日志等存哪），路径与实际一致
- [ ] 注释与 docstring 全部为中文（协议专有名词除外）
- [ ] 无魔法数字：所有科学参数均来自 `params.yaml`
- [ ] 无硬编码路径；不写 `data/raw`；不覆盖 `frozen/` 与既有 `outputs/`
- [ ] 输出走原子写出；`run.json`、`run_index.csv` 会更新
- [ ] 输出表在 `schema_registry.yaml` 中已登记；空表保留表头
- [ ] logger 输出 JSONL 到正确 `logs/{run_alias}/{M}/` 路径；无 print 兜底
- [ ] 涉筛选步骤写入 `sample_flow.csv`（n_before/n_after/原因）
- [ ] 模块状态更新为合法枚举；条件退出附 gate/exit 报告
- [ ] 编排入口统一管理 `WizardPanel` 与 `LiveStatus`，带 `--progress` 三档参数，退出时清理面板，提示与结构化结果分流
- [ ] 向导以中文编号菜单和自由输入收集运行信息，`run_alias` 必填，提交前显示计划确认页，提问限运行控制选项
- [ ] 状态、`-h` 帮助、警告、错误提示、退出说明均为中文
- [ ] 敏感性由配置驱动，无"复制改数字"代码
- [ ] 关键函数有测试且全部通过（无 skip 冒充 pass）
- [ ] 依赖已在 `environment.yml` 锁定（含 rich）；探索代码与 `src/M*` 隔离
- [ ] `tests/` 通过，`sop_unit_test_result.csv` 已生成
