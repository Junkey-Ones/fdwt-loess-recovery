# 项目系统架构

> 论文代码仓库的目录结构与工程规范。目标：**任何人在任何时间，都能从 data/raw 一键复现论文的全部图表**。
> 本架构以技术路线 V1.0 的《AI工作包_workflow搭建》《模块化思路理解》《预注册文档》为准，目录命名尽量沿用协议原文。
> 执行细则见 [[脚本书写规范]]——仓库内所有脚本必须严格按该规范书写，规范与本架构冲突时以协议原文为准。

- 项目仓库
	- README.md  `研究简介、数据来源与获取方式、环境安装、M0→M10 运行步骤、引用方式与 DOI`
	- LICENSE  `开源许可证（建议 MIT 或 CC-BY-4.0）`
	- environment.yml  `conda 环境定义，所有依赖锁定版本`
	- .gitignore  `排除 data/raw、data/interim、data/frozen、outputs、logs、__pycache__ 等`
	- workflow  `流水线编排层：DAG 调度，不放科学代码`
		- Snakefile  `建议用 Snakemake：整体运行、单模块运行、按依赖重跑、断点续跑、哈希级联失效；线性 Makefile 不满足协议要求`
		- 入口契约  `run_module(module_id, config_path=config/params.yaml, run_id, run_alias, resume=true, overwrite_frozen=false)，所有编排都走这一个入口；run_id 是协议身份（哈希），run_alias 是给人看的目录名，运行时写入各目录的 run.json 并登记 metadata/run_index.csv`
	- config  `科学参数与协议的唯一来源`
		- params.yaml  `全部科学参数（约 30 个顶级键）；代码中禁止出现科学参数的魔法数字`
		- schema_registry.yaml  `各输出表 schema 登记；未发生的表也保留空表和表头`
		- specification_matrix.yaml  `规范曲线：按估计对象（estimand）冻结的定义族矩阵（终止阈值、持续定义、降水窗口、物候、暴露版本等）`
		- deviation_log.csv  `预注册偏离台账（日期/原条款/新条款/原因/是否见过结局/影响模块/审批人/重跑范围）；无偏离时保留空表`
	- metadata  `验收、冻结与运行登记，独立于 data/`
		- source_file_manifest  `原始文件清单：版本、哈希、覆盖、许可（对应 [[原始数据清单]]）`
		- source_variable_map  `原生字段→标准变量映射`
		- protocol_freeze  `预注册/手册冻结记录，登记与手册口径差异`
		- run_index.csv  `可读别名 ↔ 完整 run_id ↔ 各路径的总索引，人和脚本都从这里查`
		- 站点与研究区验收清单  `边界 CRS/几何/许可、站点放行记录`
	- data  `所有数据文件；上游只读、原子写出`
		- raw  `原始 9 类数据+条件项（ERA5-Land、GLDAS、CHIRPS、MODIS 系列、SoilGrids、NASADEM 等），只读，README 注明获取方式`
		- interim  `中间数据；外层按数据名找，内层按运行版本选`
			- {数据名}/  `如 event_master_base、grid_pentad；产品无关数据直接放 run 目录下`
				- {run_alias}/  `可读版本名，格式 YYYY-MM-DD_短描述，如 2026-11-10_主分析、2026-11-15_终止阈值敏感性；同名目录不覆盖，旧版本保留`
					- run.json  `该次运行的完整身份：run_id = v1.3.1__{params_hash12}__{code_hash12}__{seed_id}、参数哈希、代码哈希、种子、git commit、模块状态；哈希失效与幂等判断读这里，不读目录名`
					- {product_combo}/  `产品相关数据再分：era5land__era5land / gldas21__gldas21 / era5land__chirps20 / gldas21__chirps20，另含 gldas_native_025`
		- frozen  `冻结交接表，不可覆盖（overwrite_frozen=false），输入哈希变化即下游失效`
			- {数据名}/{run_alias}/  `7 张交接表：grid_pentad、event_master、event_branch、event_exposure、grid_year、route2_person_pentad、analysis_log，及 sample_flow.csv、result_manifest.json；每个 run 目录同样带 run.json`
	- src  `所有科学代码；按模块 M0–M10 分目录`
		- M0  `协议与版本冻结：params/schema/run_id/种子、合成序列测试、原始数据实文件验收放行`
		- M1  `原始数据与 QC：解码、单位符号、日界、QA`
		- M2  `时空与土层预处理：日→73 候、层厚合成、面积加权 → grid_day、grid_pentad_base、grid_static_covariates`
		- M3  `掩膜、物候与气候态 → grid_mask、grid_phenology、grid_climatology`
		- M4  `全量事件库 → event_master_base、event_candidate_audit（episode_id 主键）`
		- M5  `结局派生：恢复轨迹、F_R、P-term、F_Z → event_master/precip/branch`
		- M6  `事件前暴露：五年 LAI、前四候深层水 → event_exposure`
		- M7  `路线一统计：Q1/Q2/Q3 → q1_/q2_/q3_*、model_* 表`
		- M8  `路线二三出口（可拆 M8a 编码结局 / M8b 门槛与建模）；只读 M1–M6，不回写，删除后路线一仍完整可运行 → route2_person_pentad、route2_exit、route2_gate`
		- M9  `稳健性：四套产品组合重跑、事件对齐、规范曲线、站点分轨`
		- M10  `独立复核与论文输出：样本流审计、≥30 事件分层复算 → sample_flow.csv、result_manifest.json、review_*`
		- 每模块目录内  `scr_XX.py（模块脚本，小写 snake_case）+ scr_XX.md（功能、输入输出、使用方法）；科学参数一律读 config/params.yaml，不设脚本级参数文件`
	- outputs  `所有计算产出，按运行版本隔离`
		- {run_alias}/  `与 data 下同名 run 目录一一对应，目录内同样放 run.json`
			- tables  `论文表：q1_recovery_distribution、q2_fr_conditional_proportion、q3_model_ldi_effects、cross_product_*、spec_*、sample_support 等（§10.3 清单）`
			- figures  `论文图：fig01_sample_flow … fig07_route2_paths`
			- models  `模型对象 + JSON 摘要（效应、区间、Holm、n_event/n_exposure/n_eff/EPV）`
			- reports  `sop_unit_test_result.csv、route2_exit_report.md、final_reproducibility_report 等`
			- review  `R6 独立复算产物：review_event_recalc 等`
	- logs  `JSONL 追加后只读；同一 run_alias 的日志永不覆盖`
		- {run_alias}/  `与 data、outputs 下的 run 目录同名`
			- run.json  `该次运行身份，与 data、outputs 三处一致`
			- module_status.csv  `M0–M10 模块状态总表（not_run/passed/descriptive_only/conditional_skipped/exited/failed），run 级唯一，M10 审计直接输入`
			- data_audit_log.jsonl  `run 级数据验收与审计事件：实文件验收、守恒检查、放行/暂缓`
			- M0/  `按模块分目录`
				- M0_{脚本名}_{ISO8601开始时刻}.jsonl  `每次脚本调用一个文件，含 level/time 消息与 stdout/stderr；按名排序即时间序`
			- M2/  `…同上，每个用过的模块一个目录`
			- （resume 续跑产生新的时间戳文件，不修改已封存的旧文件）`
	- tests  `对应《SOP 附录》§15.1 测试矩阵（U/E/G/C/L/N/P/T/S/D/R/V），含合成序列（闰年、累计边界、阈值、缺测、删失、湿窗口）；不得用 skip 冒充 pass`
	- docs  `参考资料：技术手册、SOP 附录、文献引用解释等`

## 工程规范

1. **参数唯一来源**：科学参数只在 `config/params.yaml`；改参数 → 新 `params_hash` → 新 `run_id` → 下游按哈希级联失效重跑。代码中禁止魔法数字。
2. **人机分工找版本**：目录名用可读的 `run_alias`（`YYYY-MM-DD_短描述`，同名不覆盖、旧版本保留），完整 `run_id` 与哈希写在目录内 `run.json`；哈希失效、幂等判断读 run.json，人找数据看目录名。`metadata/run_index.csv` 是两者的总索引，改名或移动 run 后必须同步更新。
3. **冻结不可变**：`data/frozen` 与已产出的 `outputs/{run_alias}` 不得覆盖（`overwrite_frozen=false`）；参数、口径或输入变更一律以新 `run_id` + 新 `run_alias` 重跑。
4. **幂等与原子性**：上游只读、原子写出、重复运行结果一致；时间戳不参与科学结果哈希。
5. **敏感性由配置驱动**：规范曲线、产品组合、暴露版本全部走 `specification_matrix.yaml` 与 `product_combo` 分区，禁止复制一套代码手工改数字。
6. **每步留痕**：`sample_flow.csv` 逐层记录 n_before/n_after 与排除原因；模块状态、审计日志、偏离台账即使"未发生"也保留空表。
7. **盲态顺序**：先审计后拟合；偏离在看过结局后发生的，只能标为后验探索。
8. **命名规范**：新字段与文件名一律小写 snake_case；时间戳统一 ISO 8601，仅用于日志文件名、run_alias 前缀与登记字段。
9. **可追溯**：论文每张图表能从 `outputs/{run_alias}/run.json` 回溯到完整 run_id（参数+代码+种子哈希）与 `data/raw` 原始文件。
