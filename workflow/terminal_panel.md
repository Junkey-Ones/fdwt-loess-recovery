# 终端面板

组件位于 `workflow.terminal_panel`。从项目根目录运行 `.\.venv\Scripts\python.exe -m workflow.run_module` 进入中文向导。五步依次为运行范围、运行版本、数据与规范、资源与显示、确认计划。按 Ctrl+B 回到上一题，按 Ctrl+Q 或 Ctrl+C 结束向导；纯文本输入还支持「返回」「帮助」「退出」。确认页可以直接修改指定组，保留已填值并重新核对执行条件。向导使用终端原生输入。

运行时默认只显示当前工作；按 `1` 看当前工作、`2` 看包含模块状态的总览、`?` 看帮助，`Ctrl+C` 中断。宽终端并列显示，窄终端纵向排列。文本模式输出阶段变化、每 30 秒摘要及最终状态。

## 后续模块如何接入

- 编排入口用 `WizardPanel(title)` 的上下文管理器收集运行控制选项。每道题调用 `panel.ask(prompt, check, default, details=...)`。校验函数返回有效值，输入无效时抛出带中文说明的 `ValueError`。
- 单选题调用 `panel.menu(prompt, options, default, section=...)`。每项提供内部值、中文标签和用途说明，界面自动编号并标记默认项。提交前的确认题汇总模块顺序、数据来源、规范和四类输出路径。
- 运行阶段由编排入口统一管理 `LiveStatus(mode, render)`。先调用 `start()`，在 `finally` 中调用 `close()`。渲染读取线程安全快照。模块通过 `workflow.progress.emit` 上报阶段、计数和状态，仍兼容旧三参数回调。
- `auto` 在支持的终端启用 Rich，重定向时降级为逐行提示。`panel` 要求终端支持光标更新，`plain` 使用逐行输出。面板和提示使用标准错误，结构化结果使用标准输出。

Windows 下建议从 Windows Terminal 启动。向导运行在备用屏幕，答题结束后切换到运行进度显示。

阶段速度基于 30 秒窗口内至少两次有增量的有效工作量更新。模块剩余时间基于至少两条签名匹配的成功记录，配合当前阶段的速度估计；缺乏可靠依据时显示暂无法估算。计时记录及 ETA 样本覆盖、绝对误差中位数写入本机运行目录的 `progress_*.json`。没有依据时显示暂无法估算。见[事件与估时](progress.md)。

## 交互与接力更新

Windows 交互终端的单选菜单使用方向键与回车；纯文本环境使用编号。颜色和进度显示自动选择，命令行仍可用 `--progress` 指定。新别名选择已有运行后，可选择连续复用 M1 至 M2–M6，再执行至 M3–M7；提交前确认来源和终点。来源必须通过冻结身份、代码和配置兼容、回执链和哈希校验。M8–M10 的跨别名接力未开放。交互终端结束显示中文摘要，高级入口和重定向保留 JSON。

进度事件可带 `operation` 与 `path`，只在实际可观测的操作边界报告；没有可靠计数或耗时依据时不虚构进度。文本与 Rich 面板均显示已报告路径。

M0 协议与登记读取、M1 报告写入、M2 原始文件哈希、M3–M10 的交接表读取及主要表写入会报告可观测路径。纯文本模式在切换已报告文件时立即输出；科学库内部、并行工作进程及尚未接入事件的读写仍以阶段信息表示。
